# Unix V6++

`Unix V6++` 是同济大学操作系统课程的教学系统。本仓库维护的是可在 `Linux` 本机构建和运行的一套工程化版本，重点在于把 `内核`、`用户程序`、`磁盘镜像`、`Bochs/QEMU` 运行链路统一到同一项目中。

## 运行环境

以下运行环境已经过测试：

| 项目 | 版本/信息 |
|---|---|
| `Host OS` | `Linux 6.19.10-zen1-1-zen x86_64` |
| `CMake` | `4.3.1` |
| `GCC` | `15.2.1 20260209` |
| `G++` | `15.2.1 20260209` |
| `NASM` | `3.01` |
| `Ninja` | `1.13.2` |
| `QEMU` | `10.2.2` |
| `Bochs` | `2.8` |

构建约束：

- 仅支持 `Linux host`（顶层 `CMakeLists.txt` 显式限制）。
- 目标架构为 `i386`，核心编译/链接参数为 `-m32`、`elf32-i386`。
- 若本机未安装 `bochs-gdb` 或 `qemu-system-i386`，对应目标不会生成。

## 物理内存与磁盘占用约定

### 1. 内存总参数

- 虚拟机总内存：`32 MiB`
  - `Bochs`: `megs: 32`
  - `QEMU`: `-m 32M`
- 页大小：`0x1000`（`4 KiB`）
- 用户物理页池起始：`0x00400000`
- 默认用户物理页池大小：`32 MiB - 4 MiB = 28 MiB`

### 2. 物理内存关键区域表

| 区域 | 起始物理页 | 结束物理页 | 物理地址范围（参考） | 对应功能 |
|---|---|---|---|---|
| 低地址 `runtime` 物理页 | `0x000 (0)` | `0x000 (0)` | `0x00000000-0x00000FFF` | 引导阶段把 `runtime` 复制到该页，供首次用户态路径使用。 |
| 内核程序段装载窗口 | `0x100 (256)` | `0x17F (383)` | `0x00100000-0x0017FFFF` | 内核镜像物理装载区（`KERNEL_MEM_START_ADDR=0x100000`，`KERNEL_SIZE=0x80000`）。 |
| 内核堆对应物理区 | `0x180 (384)` | `0x1FF (511)` | `0x00180000-0x001FFFFF` | 内核堆（`KERNEL_HEAP_SIZE=0x80000`）对应的物理后备区。 |
| 页表固定区 | `0x200 (512)` | `0x202 (514)` | `0x00200000-0x00202FFF` | 固定保留：共享核心页表、共享 `0#` 用户页表、`0#` 进程页目录。 |
| 页表/页目录分配池 | `0x203 (515)` | `0x3FF (1023)` | `0x00203000-0x003FFFFF` | `KernelPageManager` 使用的页目录/私有用户页表分配池。 |
| 用户物理页池 | `0x400 (1024)` | `0x1FFF (8191)`（默认 `32 MiB`） | `0x00400000-0x01FFFFFF` | 用户态驻留页来源，缺页分配与 `fork COW` 都来自此池。 |
| `zero page` | `0x400 (1024)` | `0x400 (1024)` | `0x00400000-0x00400FFF` | 全局共享零页：`BACKING_ZERO` 首次映射只读零页，写入时 `COW` 分裂。 |

### 3. 虚地址规则与段排列

当前虚地址相关规则如下：

1. 链接脚本把 `.text` 固定到 `0x00401000`，即代码段从虚拟页 `0x401` 开始。
2. 链接顺序为 `.text -> .data -> .rodata -> .bss`，并且每段之间执行 `4096` 字节页对齐。
3. 进程装载时，内存区域顺序固定为 `runtime -> code -> [data/rodata/bss] -> heap -> stack`。
4. `heap` 起点取 `data/rodata/bss` 页对齐后的末尾；`stack` 位于用户空间高地址端并向下增长。
5. 核心栈与 `PPDA` 共用一个虚拟页 `0xC03FF`（`[0xC03FF000, 0xC0400000)`）：高地址端作为核心栈（初始化 `ESP/EBP/TSS.ESP0=0xC0400000`），低地址端为 `PPDA` 区（`u` 结构驻留区）。

| 区域 | 起始虚拟页 | 结束虚拟页 | 虚拟地址范围（参考） | 排列规则说明 |
|---|---|---|---|---|
| 用户空间总范围 | `0x000` | `0x7FF` | `0x00000000-0x007FFFFF` | 固定 `8 MiB` 用户空间。 |
| `runtime` 区 | `0x000` | `0x000` | `0x00000000-0x00000FFF` | 低地址运行时页，先于普通程序段存在。 |
| `code (.text)` | `0x401` | `AlignUp(.text_end)-1` | 从 `0x00401000` 开始 | 固定起点 `0x401` 页，按 `ELF` 实际大小向后扩展。 |
| `data (.data)` | `AlignUp(.text_end)` 所在页 | 随段大小确定 | 紧随 `code` 的页对齐位置 | 先于 `rodata`、`bss` 排列。 |
| `rodata (.rodata)` | `AlignUp(.data_end)` 所在页 | 随段大小确定 | 紧随 `data` 的页对齐位置 | 只读段，装载后按只读保护策略处理。 |
| `bss (.bss)` | `AlignUp(.rodata_end)` 所在页 | 随段大小确定 | 紧随 `rodata` 的页对齐位置 | 未初始化数据段，按零页后备策略处理。 |
| `heap` | `AlignUp(data/rodata/bss_end)` 所在页 | `brk` 所在页（动态） | 动态变化 | 由 `SetHeapBreak` 扩展/收缩。 |
| `stack` | `AlignDown(USER_SPACE_END-stackSize)` | `0x7FF` | 顶端为 `0x00800000`（不含） | 位于高地址端，按缺页规则向低地址增长。 |
| `PPDA/u` 区（ring0，同页低地址） | `0xC03FF` | `0xC03FF` | `0xC03FF000` 起的低地址子区 | 保存当前进程 `u` 结构等 `PPDA` 数据。 |
| 核心栈（ring0，同页高地址） | `0xC03FF` | `0xC03FF` | `[0xC03FF000, 0xC0400000)`，栈顶 `0xC0400000` | 与 `PPDA` 同页，高地址端向低地址增长。 |

### 4. 磁盘布局表

磁盘镜像统一为 `build/c.img`，几何参数固定为：`20 cylinders` × `16 heads` × `63 sectors/track`，扇区/块大小 `512 bytes`，总大小 `10,321,920 bytes`。

| 区域 | 起始块 | 结束块 | 块数 | 对应功能 |
|---|---:|---:|---:|---|
| `Boot` | `0` | `0` | `1` | 启动扇区（bootloader）。 |
| `Kernel` | `1` | `999` | `999` | 内核二进制区。 |
| `SuperBlock` | `1000` | `1001` | `2` | 文件系统超级块。 |
| `Inode` | `1002` | `1999` | `998` | inode 区。 |
| `Data` | `2000` | `17999` | `16000` | 数据区（文件内容与目录项）。 |
| `Swap` | `18000` | `20159` | `2160` | 交换区。 |

## 更新记录

### 1. 内存离散化 + 按需分页 + COW + `zero page`

- 物理页管理改为 `bitmap` 跟踪，页分配/释放接口统一为按页操作（`AllocatePages/FreePages`）。
- 进程用户内存不再用“单段粗粒度”描述，改为 `Region + PageInfo` 两层模型：
  - 区域层记录 `runtime/code/rodata/data/bss/heap/stack`。
  - 页层记录 `FREE/RESERVED/RESIDENT` 状态和后备来源。
- `exec` 装载路径改为“先建布局、后缺页回填”：
  - `code/rodata` 可共享映射。
  - `data` 走文件后备按需读入。
  - `bss/heap/stack` 走 `BACKING_ZERO`。
- 新增 `fork` 后可写页 `COW`：父子进程先共享只读页，首次写入触发分裂复制。
- 固定保留 `zero page`（用户物理池第一页）作为全局零页：
  - 缺页先映射零页（只读）。
  - 写故障再做 `COW` 分裂，减少冷启动内存占用。
- 缺页处理支持栈自动增长（受 `heap/stack` 间隙约束），并统一通过页表重建与 `TLB` 刷新保证一致性。

### 2. 迁移到 Linux，支持 `ELF` 解析与 `i386 ELF` 可执行

- 构建主机策略统一到 `Linux-only`，清理旧的 Windows 兼容路径。
- 可执行装载主路径切到 `ELF`：
  - 校验 `ELF magic`、`32-bit`、`little-endian`、`ET_EXEC`、`EM_386`。
  - 解析 `.text/.data/.rodata/.bss` 并生成进程内存布局。
- 用户程序链接目标统一为 `elf32-i386`，入口与段布局按 `i386` 约定处理。
- 引导支持 `ELF toolchain` 构造/析构流程（`.init_array`、`.fini_array`），同时保留对旧 `.ctors/.dtors` 的兼容处理。

### 3. 迁移到 `CMake` 构建系统

- 顶层构建统一为 `CMake`：内核、用户程序、文件系统工具、镜像生成都纳入同一依赖图。
- 镜像生成流水线固定为：
  - 先构建 `boot.bin`、`kernel.bin`、用户程序与 `fs-tools`。
  - 再由 `GenerateDiskImage.cmake` 组装 `build/c.img`。
- `Bochs` 配置改为模板生成，`nodebug/gdb/gui` 三种模式由同一模板参数化输出。
- 构建产物目录收敛到 `build/`，便于清理、调试和 CI 复现。

### 4. 迁移到 `QEMU` 虚拟机

- 新增统一入口脚本 `qemu/run_qemu.sh`，通过 `QEMU_MODE` 切换运行模式。
- 支持三种模式：
  - `curses`：终端模式
  - `gui`：图形模式
  - `gdb-curses`：终端模式 + `gdbstub :1234`
- `QEMU` 与镜像路径统一绑定 `build/c.img`，与 `CMake image` 目标保持一致。
- VS Code 任务链路与 `CMake target` 对齐，形成“配置 -> 构建镜像 -> 启动虚拟机”的一致工作流。

### 5. 双区域滚动条

- 当前屏幕支持两个独立滚动区域：`Diagnose` 诊断区与 `CRT` 终端区。
- 两个区域各自维护历史缓冲与视口，滚动互不影响。
- 快捷键映射：
  - `Home/End`：滚动 `Diagnose` 区域。
  - `PgUp/PgDn`：滚动 `CRT` 区域。
- 滚动到尾部后会自动回到 `FollowTail` 状态，继续跟随最新输出。
