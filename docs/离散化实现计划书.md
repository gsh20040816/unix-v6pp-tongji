# Unix V6++ 离散化实现计划书

## 1. 目标

本计划书面向当前仓库代码，目标是在保留 Unix V6++ 进程、文件系统和系统调用主体结构的前提下，将现有“连续物理区 + 交换区”的进程内存模型改造为“页式离散分配 + 每进程页表”的实现。

本轮实现的主目标如下：

1. 用户区采用页式离散分配，相邻逻辑页不再要求映射到相邻物理页框。
2. 进程切换基于 `CR3` 切换页目录，不再依赖运行时把页表复制进公共页目录。
3. 保留 PPDA 独立映射机制，使核心态 `0x3ff#` 页面始终映射当前进程的 PPDA。
4. 取消“进程图像整体连续搬运”的基本假设。
5. 第一阶段不依赖交换区完成 `fork/exec/exit/brk/栈增长` 的基本功能。
6. 在第一阶段稳定后，再实现写时复制（COW）和零页等优化。

## 2. 当前代码基线与主要矛盾

### 2.1 已有基础

当前仓库已经具备以下基础能力：

1. 核心高地址映射已经建立，内核页表初始化逻辑已存在。
2. 页故障异常入口已经接通，并且已有用户栈自动扩展雏形。
3. 用户地址空间的两张页表抽象已经存在，`MemoryDescriptor` 已能描述正文段、数据段和栈段的虚拟布局。
4. `fork/exec/exit/brk` 等流程已经齐备，便于在现有框架上替换内存实现。

### 2.2 现有实现的核心问题

当前实现虽然使用了分页硬件，但内存管理模型仍然是连续物理区模型，主要表现在：

1. `Process::p_addr` 同时承担 PPDA 地址和整段进程图像基址的角色。
2. `Swtch()` 仍依赖公共页目录，切换后再调用 `MapToPageTable()` 修补用户态映射。
3. `MemoryDescriptor::EstablishUserPageTable()` 通过连续递增的物理页号构造映射，默认正文、数据、栈都连续。
4. `NewProc()` 通过分配一整块物理内存并逐字节复制，完成父子进程图像复制。
5. `Expand()`、`SBreak()` 和 `SStack()` 都依赖“扩大或缩小整块连续图像”。
6. `Exec()` 仍然按“正文连续 + 数据连续 + 栈连续”的方式重新装载。
7. `Exit()`、`Sched()`、`XSwap()` 仍然围绕交换区设计，与实验要求“不使用盘交换区”矛盾。

因此，本次离散化不是补若干页表字段，而是一次内存模型替换。

## 3. 总体设计

### 3.1 物理内存布局

沿用实验文档建议，物理内存逻辑上分为以下区域：

1. `0#` 页框：保留给 `runtime/ExecShell` 等用户态入口代码。
2. `[1M, 1.5M)`：内核代码和静态数据。
3. `[1.5M, 2M)`：内核堆。
4. `[2M, 4M)`：页目录和页表区。
5. `[4M, PHY_MEM_SIZE)`：用户物理页区，存放 PPDA、正文页、数据页、栈页。

### 3.2 页表模型

每个普通进程维护一份二级页表，包含：

1. 1 个页目录，进程私有。
2. 1 张核心页表，所有进程共享。
3. 1 张 `0#` 用户页表，所有进程共享。
4. 1 张 `1#` 用户页表，进程私有。

说明：

1. 核心页表负责映射内核高地址空间。
2. 核心页表最后一个 PTE 专门映射当前进程 PPDA。
3. `0#` 用户页表负责公共低地址映射，至少包括逻辑页 `0`。
4. `1#` 用户页表负责正文、数据、栈等真正的用户页映射。

### 3.3 进程内存元数据

建议对 `Process` 和相关结构做如下调整：

1. `p_addr` 保留，但语义收敛为 PPDA 的物理起始地址。
2. 新增 `p_pgTable`，表示该进程页目录的内核虚拟地址。
3. `p_size` 不再表示“一整块连续图像长度”，改为“进程私有可写页占用总字节数”或保留为统计字段，不再驱动物理搬运。
4. `Text` 增加正文页表归属信息，例如 `x_pgTable` 或正文页框数组引用。
5. `MemoryDescriptor` 保留段级语义，但需要增加按页管理能力。

### 3.4 物理页管理模型

建议引入统一的页框元数据数组 `Page[]`，每个页框记录：

1. 引用计数。
2. 所属区域或用途。
3. 是否可分配。

第一阶段至少要求能够支持：

1. 单页框分配与释放。
2. 页表区页框分配。
3. 用户区页框分配。
4. 共享正文页引用计数。
5. 为后续 COW 复用引用计数能力。

## 4. 实施阶段

### 阶段 A：重构基础分页设施

目标：建立“每进程独立页目录”的最小运行基础。

任务：

1. 重构 `PageManager`，从“连续区分配器包装”改为“按页框分配器”。
2. 区分页表区和用户页区的页框分配入口。
3. 扩展 `Process` 结构，加入 `p_pgTable`。
4. 重写 `FlushPageDirectory`，支持传入指定页目录物理地址。
5. 重写 `SwtchUStruct`，在更新 PPDA 映射后切换到目标进程页目录。
6. 在 `main0` 和 `SetupProcessZero()` 中初始化 0# 进程页目录。

交付标准：

1. 0# 进程与 1# 进程能够在独立页目录下正常切换。
2. 调度过程中不再调用 `MapToPageTable()` 修补映射。
3. 共享核心页表和共享 `0#` 用户页表工作正常。

### 阶段 B：重写用户页映射模型

目标：让 `MemoryDescriptor` 真正按页记录映射，不再依赖连续物理页号。

任务：

1. 保留段级信息 `m_TextStartAddress`、`m_DataStartAddress`、`m_StackSize`。
2. 将 `MapEntry()` 从“连续物理页号递增填充”改为“按外部传入页框数组或逐页分配结果写入”。
3. 删除或废弃 `MapToPageTable()` 的公共页目录灌入逻辑。
4. 增加页表清理接口，用于 `exec/exit/fork` 前后的逐页回收。
5. 增加按虚拟页查找 PTE 的辅助接口，供 `PageFault`、`brk` 和 `exit` 使用。

交付标准：

1. 普通进程可以持有独立的 `1#` 用户页表。
2. 用户页框分配结果允许完全不连续。
3. 任意用户逻辑页都可以直接定位对应 PTE。

### 阶段 C：重写 Exec

目标：单进程加载用户程序时，完全基于离散页框建立进程映像。

任务：

1. 保留 PE 解析流程和参数准备流程。
2. 释放旧用户页和旧正文引用时，改为逐页回收，而不是 `Expand(USIZE)`。
3. 为新正文、数据、栈底页逐页申请物理页框。
4. 将这些页框写入新页表。
5. 重新实现正文共享机制。
6. 参数页单独准备后映射到栈底逻辑页。
7. 保留用户态从逻辑页 `0` 进入 `runtime()` 的现有策略。

交付标准：

1. `exec("/Shell.exe")` 能正常启动 shell。
2. 正文页可共享，数据页和栈页私有。
3. `Exec` 全流程不依赖交换区。

### 阶段 D：重写 Fork

目标：实现离散页模型下的进程复制。

第一版采用“共享正文 + 复制可写页”的直接实现，不立即引入 COW。

任务：

1. 为子进程分配新页目录和私有 `1#` 用户页表。
2. 复制父进程页表结构。
3. 正文页保持共享。
4. PPDA 单独分配并复制。
5. 数据页、栈页逐页分配新页框并复制内容。
6. 修正子进程返回路径，确保调度后仍按现有 `NewProc()` 语义返回。

交付标准：

1. `fork()` 后父子进程都能继续运行。
2. 父子修改私有数据时互不影响。
3. 不再申请整块连续进程图像。

### 阶段 E：重写 Exit / Wait

目标：去除对交换区保存僵尸进程状态的依赖。

任务：

1. `Exit()` 逐页释放 PPDA 之外的用户页。
2. `Exit()` 中正文引用计数按共享页模型回收。
3. `Wait()` 直接从僵尸进程控制块中读取退出码和统计信息。
4. 如有必要，在 `Process` 中增加僵尸态字段保存 `wait` 结果。

交付标准：

1. 子进程退出后，父进程 `wait()` 能回收其状态。
2. 用户页和页表页均能正确释放。
3. 全流程不访问 swapper。

### 阶段 F：重写 brk 与栈增长

目标：让可写段扩展逻辑适应离散分页。

任务：

1. `SBreak()` 改为按需增删数据段末尾页。
2. `SStack()` 改为缺页时只为新栈页分配一个页框。
3. 删除 `Expand()` 中的整块搬迁逻辑，或将 `Expand()` 重定义为统计更新函数。
4. 页故障处理程序基于 `CR2` 精确定位访问页，并判断是否属于合法栈增长。

交付标准：

1. 数据段增长不触发整段搬迁。
2. 栈增长一次只分配一个页框。
3. 页故障处理逻辑清晰区分“合法增长”和“非法访问”。

### 阶段 G：去除换出调度路径

目标：在课程要求范围内简化调度器。

任务：

1. 关闭或裁剪 `Sched()` 中的换入换出逻辑。
2. 停用 `XSwap()`、`RunIn`、`RunOut`、`SSWAP` 等依赖交换区的调度路径。
3. 保留基本调度、睡眠、唤醒和时钟中断优先级调整逻辑。

交付标准：

1. 系统无交换区也可稳定运行基础用户程序。
2. 调度器不再因等待 swap 而阻塞。

### 阶段 H：COW 与零页优化

目标：在基础功能稳定后实现性能优化。

任务：

1. 为用户可写页引入引用计数。
2. `Fork()` 对可写页改为共享 + 写保护。
3. `PageFault()` 对写保护异常执行 COW。
4. 如有余力，实现零页并将 `bss` 映射到零页。

交付标准：

1. `fork()+exec()` 的物理页分配明显减少。
2. 对共享可写页的首次写入能正确触发复制。

## 6. 里程碑

### 里程碑 M1：最小分页切换跑通

判断标准：

1. 0# 和 1# 进程在独立页目录下切换正常。
2. shell 可启动。
3. `MapToPageTable()` 已不参与调度切换。

### 里程碑 M2：单进程离散装载跑通

判断标准：

1. `exec` 可以建立离散用户页映射。
2. 正文、数据、栈页可不连续。
3. shell 能执行基本命令。

### 里程碑 M3：无交换区多进程跑通

判断标准：

1. `fork` 后父子均可运行。
2. `wait/exit` 正常。
3. `brk` 和栈增长正常。

### 里程碑 M4：COW 优化完成

判断标准：

1. `fork` 后初始物理页复制减少。
2. 首次写入触发缺页复制。
3. 系统稳定运行多轮 `fork/exec/exit`。

## 7. 测试计划

### 7.1 基础测试

1. 系统启动到 shell。
2. shell 执行简单命令。
3. 连续创建并退出多个短进程。

### 7.2 内存管理测试

1. 构造小程序验证正文、数据、栈地址访问。
2. 验证相邻逻辑页映射到不相邻物理页框。
3. 验证 `brk` 扩展和回缩。
4. 验证深栈访问触发合法栈增长。
5. 验证非法地址访问触发 `SIGSEGV`。

### 7.3 共享正文测试

1. 同一程序多次 `exec`。
2. 检查 `Text` 引用计数递增递减。
3. 验证正文释放时机正确。

### 7.4 COW 测试

1. `fork` 后父子先只读访问共享页。
2. 子进程先写，再检查父进程视图。
3. 父进程后写，再检查引用计数与页内容。

## 8. 风险与应对

### 风险 1：旧代码中 `p_addr` 被过度复用

应对：

1. 尽早把 `p_addr` 语义固定为 PPDA 页框地址。
2. 所有依赖“整段物理图像”的路径逐个替换，不混用两套语义。

### 风险 2：页表切换后核心态访问当前 `u` 结构失效

应对：

1. 保留核心页表最后一个 PTE 指向当前进程 PPDA 的机制。
2. 优先完成 `SwtchUStruct` 改造后，再推进其它模块。

### 风险 3：一次同时改动过大导致无法启动

应对：

1. 严格按里程碑推进。
2. 每个阶段只替换一类关键路径。
3. 每完成一个阶段立即构建和启动验证。

### 风险 4：COW 与基础离散分页同时推进复杂度过高

应对：

1. 先完成无 COW 的稳定版本。
2. COW 单独作为后续优化阶段。

## 9. 建议的实际执行顺序

推荐按以下顺序实施：

1. 先改页框分配器和进程页目录字段。
2. 再改 `Swtch()` 和 `CR3` 切换。
3. 然后重做 `Exec()`，确保单进程装载正常。
4. 再实现不带 COW 的 `Fork()`。
5. 之后重写 `Exit()` 和 `Wait()`。
6. 再做 `brk`、栈增长和页故障逻辑。
7. 最后裁剪 swap 路径并视时间加入 COW。

## 10. 本阶段提交目标

当前提交的目标不是立即修改内核实现，而是完成以下管理动作：

1. 固化实现方向，避免后续开发偏回连续内存模型。
2. 为后续编码建立分阶段任务顺序。
3. 形成可对照的验收项和风险清单。

后续编码应严格围绕本计划推进，避免在 `fork/exec/exit/brk/page fault` 路径上同时保留两套长期共存的内存模型。
